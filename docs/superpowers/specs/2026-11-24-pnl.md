- 起草：2026-11-24
- 来源：intent（未公开）（已接受）、[ADR-0024](../../decisions/0024-pnl-ledger-fifo-per-platform.md)、实测 [盈亏数据来源 research](../../research/2026-11-24-pnl-data-sources.md)
- 视觉基准：claude.ai 画布「SkinPulse 看板视觉稿」最下面一组「盈亏」（2026-11-24 定稿），浅色、深色各一张。实现和视觉稿有出入时以本 spec 为准，本 spec 没写到的以视觉稿为准。视觉稿上的数字是 11-24 的试算，和本 spec 的对账口径（§4.3）略有出入，以 spec 为准。
- 标记约定同主 spec：**〔未实现〕** 表示还只是计划。
- plan：盈亏 plan（未公开）（2026-11-24 批准）
- 实现：2026-11-24 完成（plan（未公开），实现上的偏离都记在 plan 里，本 spec 已同步）。多账号一期先合并，盈亏随后。

## 0. 一句话

每天夜里把悠悠的买卖订单同步进库，同账号、同平台、同模板先进先出配对，算出已实现盈亏和持仓的浮动盈亏，并核对每件持仓现在在库存、租出还是去向不明。看板新开一页「盈亏」，焦点是「总盈亏」一个数。

## 1. 范围

**一期做：**
- 同步悠悠买入、卖出订单（只要「已完成」），卖出要拿到实际到手价。
- 纯逻辑：先进先出配对、已实现、持仓、浮动（按市价、按到手价两种）。
- 每天一次持仓快照：每个模板持有几件、成本、市价、在哪（库存 / 租出 / 去向不明）。
- 23:50 的价格快照顺带覆盖持仓模板（市价来源，§4.4）。
- 接口 `/api/pnl*`、新页 `/pnl`「盈亏」。
- CLI：`pnl import`（一次性导入历史）、`pnl run`（手动跑一次每日任务）、`pnl show`。
- 配置 `[pnl]`。

**一期不做：**
- 持仓走势曲线（二期，要先攒快照）。页面上「持仓走势」只显示空状态。
- 简报加一行（二期）。
- BUFF 的买卖、跨账号转移的配对（等多账号与 BUFF；§9）。
- 租金收入、提现费。
- 推送。盈亏不进任何推送。
- 在看板上手工改账（标记「已在别处卖出」之类）。

## 3. 数据（迁移 0016；0014 是多账号，0015 是暂停单检测）

### 3.1 `trade_order`：买卖订单

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | Integer PK | |
| `account_id` | Integer，非空 | 现在都是 1。多账号一期合并后照它的约定 |
| `platform` | String(16) | `YOUPIN`；以后 `BUFF` |
| `order_no` | String(32) | 平台订单号。唯一键 (`platform`, `order_no`) |
| `side` | String(4) | `buy` / `sell` |
| `template_id` | Integer | `productDetail.commodityTemplateId` |
| `hash_name` | String | `productDetail.commodityHashName`（对租出、对 SteamDT 价都靠它） |
| `name` | String | `productDetail.commodityName` |
| `qty` | Integer | `commodityNum` |
| `amount` | Numeric(12,2) | 成交总价（元）= `totalAmount / 100` |
| `net_amount` | Numeric(12,2)，可空 | 卖出：详情 `revenue.amount`；买入：等于 `amount`（买方不收费） |
| `detail_checked` | Boolean | 卖出详情查过了（没有到手价也不再查，评审 2026-11-24 加） |
| `net_exact` | Boolean | 卖出到手价是详情给的（true），还是按 `amount × (1 − 手续费)` 向下取整到分估的（false） |
| `sub_type` | Integer | `orderSubType`（5 = 求购成交） |
| `asset_id` | String，可空 | `productDetail.assertId`。只做记录，不用来配对（research §4） |
| `created_at` | UtcDateTime | `createOrderTime`（毫秒时间戳，UTC） |
| `finished_at` | UtcDateTime，可空 | `finishOrderTime` |
| `fetched_at` | UtcDateTime | |

- 对手昵称、头像、Steam ID、报价号**不入库**。
- 只存 `orderStatus = 340`（已完成）。同步时遇到别的状态的行跳过，记一条 DEBUG。
- 已有的行不改，只补 `net_amount`（详情拿到以后）。

### 3.2 `pnl_position`：每天的持仓快照

一天一个账号一个模板一行，唯一键 (`date`, `account_id`, `platform`, `template_id`)。

| 列 | 说明 |
|---|---|
| `date` | 快照覆盖的本地日期 D |
| `account_id`、`platform`、`template_id`、`hash_name`、`name` | |
| `qty`、`cost` | 先进先出后还没卖掉的件数、这些批次的买入成本合计 |
| `first_bought_at` | 最早一批的买入时间 |
| `inv_qty`、`lease_qty`、`unknown_qty` | 在库存、租出、去向不明各几件（§4.3），三者之和 = `qty` |
| `price` | 单件市价（§4.4），缺失为 NULL，**不填 0** |
| `price_src` | `steamdt` / `inventory` / NULL |
| `price_flag` | NULL / `thin`（在售少）/ `spread`（悠悠和 BUFF 差得多） |

### 3.3 `pnl_daily`：每天的汇总

唯一键 (`date`, `account_id`)。列：`realized_total`（截至 D 的累计已实现）、`realized_day`、`qty`、`cost`、`value_mkt`、`value_net`、`unpriced_qty`、`inv_qty`、`lease_qty`、`unknown_qty`、`unknown_cost`、`youpin_pnl`（悠悠库存接口的 `profitAndLossTotal`）、`youpin_pnl_n`（它覆盖的件数）、`lease_rent_day`（租出中日租金合计，只记录不算盈亏）、`unbooked_inv_qty`、`unbooked_inv_value`（库存里没有买入记录的件数、市价）、`computed_at`。二期的曲线就读这张表。

## 4. 计算（`analysis/pnl.py`，纯逻辑、无 IO）

输入是 `trade_order` 行、库存和租出的解析结果、价格；输出 `Ledger`。所有阈值是模块里有名有姓的常量，注释写来历。

### 4.1 先进先出

- **跨号、跨平台**（[ADR-0025](../../decisions/0025-pnl-cross-platform-matching.md)，2026-11-25 实现）：按 `hash_name`（英文名）认同一件饰品，`hash_name` 空的退回按 `template_id`。组内买入按 `created_at` 升序排成批次（一笔买入一批，`qty` 件，单件成本 = `amount / qty`），每批记着是哪个号、哪个平台买的。
- 卖出按 `created_at` 升序处理：只消耗**卖出之前**买入的批次，**先消同号同平台的**（按买入时间），不够再消其余号、其余平台的（按买入时间），消够 `qty` 件为止。
- 持仓按买入的号、平台、模板汇总剩余批次；已实现记在卖出的号上。
- 消不够（之前的批次没了）：这笔卖出整笔记「成本未知」，**已消掉的部分退回**，不做部分配对。理由：部分配对的盈亏没有意义，而且会让同一笔卖出一半算一半不算。
- 每笔卖出产出：配到的批次列表（买入时间、单价、件数）、成本合计、到手价、盈亏 = `net_amount − 成本`。
- 每次全量重算（几百笔订单，毫秒级），不存配对结果。

### 4.2 已实现

- 已实现 = 所有配上了的卖出的（到手价 − 成本）之和。
- 到手价：`net_amount`（详情给的，已扣手续费）。详情还没拿到时，按 `amount × (1 − fees[平台])` 向下取整到分估算，`net_exact = false`，页面不单独标（差别在一分钱以内，research §3）。
- **提现费不扣**（ADR-0024）。
- 每月已实现：按卖出 `created_at` 的本地月份汇总。

### 4.3 持仓在哪（对账）

所有号的库存、租出都拉完以后，一次分配（2026-11-25 正式库：持有 351 件，库存 242、租出 48、不在库存 61）：

1. **库存**：悠悠库存和 BUFF 库存看到的是同一个 Steam 库存，按 assetid 合并去重，按 `hash_name` 计数（悠悠库存缺英文名的按 `Item` 补）；最多分到持有件数。
2. **租出**：悠悠租出列表（按 `commodityHashName`），同上封顶。
3. 剩下的 = **不在库存**（2026-11-25 前叫「去向不明」）：库存和悠悠租出里都没有，也没在悠悠或 BUFF 卖掉。用户确认多半是在 **BUFF App 里出租**了（网页拿不到出租列表）。

- 不在库存的**照样算进持仓、按市价估值**：成本是真金白银，不算进去反而会让盈亏好看。页面单独列件数和成本（§7.2）。
- 只给要写快照的号分配；停用的号的持仓不写、也不占库存（它的订单照样参与配对）。
- 库存、租出里有、账上没有的（不是在悠悠买的），不进持仓。库存里这部分的件数和市价记进 `pnl_daily.unbooked_inv_*`，页面一行带过。
- 跨号转移：库存是全部号合起来分配的，账户 A 买的、现在在账户 B 库存里的件，算「库存」（仍归账户 A 的批次，成本跟着走）。

### 4.4 市价

- **单件市价 = 当天 23:50 价格快照里的悠悠在售最低价**（`price_daily`，`platform = YOUPIN`，`sell_price`）。D 那天的快照缺了（睡着），往前最多 7 天找最近一天的（实现时加的）。23:50 的快照改成也覆盖**持仓模板**（前一天 `pnl_position` 里 `qty > 0` 的，加上活跃求购单的），见 §5.1。
- 快照里没有（SteamDT 没这个饰品、或那天请求失败）：退回悠悠库存接口里同模板的 `marketPrice`（中位数），`price_src = inventory`。再没有就 NULL，这个模板不进市值，计入 `unpriced_qty`，页面写「N 件没有市价」。
- 为什么用 SteamDT 而不用悠悠库存的 `marketPrice`：库存外的（租出、去向不明）也要有价，而两者在库存里的 175 个模板上几乎一样（悠悠在售 / 库存市价的中位数 1.00，第 10 百分位 0.97，只有 2 个差出 20%；2026-11-24 试算）。一个来源，口径一致。
- **异常价只标不剔**（`price_flag`）：
  - `thin`：悠悠在售件数 < `pnl.thin_count`（默认 3）。试算 258 个模板里 1 个（AUG | 变色龙（破损不堪），2 件在售）。
  - `spread`：悠悠在售 / BUFF 在售 不在 [1 / `pnl.spread_ratio`, `pnl.spread_ratio`]（默认 1.5）。试算 258 个里 3 个，都是 1 元以下的印花、涂鸦。比值的第 5、95 百分位是 0.88、1.21。
  - 试算里看着离谱的涨幅（FN57 | 怒氓 成本 37、现价 295；法玛斯 | 幻灭之旅 21 → 232）**是真的**：悠悠、BUFF 都有一百多件在售，价格对得上。所以不剔除，只在单品表里给这两种标记一个小提示。

### 4.5 浮动

- 按市价：Σ(`price × qty`) − Σ`cost`（只算有价的模板；没价的成本也不算，免得把「没价」当成「跌到 0」）。
- 按到手价：市价 × (1 − `valuation.undercut`) × (1 − `valuation.fees[平台]`)，其余同上。不扣提现费。
- 默认展示按 `pnl.basis`（默认 `market`）；接口两种都给，页面切换不重新请求。
- 总盈亏 = 已实现 + 浮动（按当前选的口径）。

## 5. 任务

### 5.1 23:50 价格快照（改）

`take_price_snapshot` 的模板集合从「活跃求购单的模板」改成「活跃求购单的模板 ∪ 最近一次 `pnl_position` 里 `qty > 0` 的模板」。SteamDT 批量 1 次 / 分钟、一次 100 个，现有的冷却不变；按作者账号多 2 批左右（约 2 分钟）。

### 5.2 每日盈亏（`services/pnl.py`，00:45）

`pnl.run_at`（默认 00:45，在 00:30 估值之后），算**前一天** D。每个有 token 的悠悠账号依次：

1. **买入、卖出**：各从第 1 页往后翻，不满一页、到 `pnl.max_pages`，或者**整页都是已入库的单**才停（有新有旧的页之后还要再看一页：完成得晚的单会排在已知单后面）。页间按 `youpin.page_sleep_s` 等。平时各 2 页。首次导入不看已知单，一直翻到不满一页（中途断了下次能接着翻）。（评审 2026-11-24 改：原来「碰到一个已知单就停」会漏单。）
2. **卖出详情**：`net_exact = false`、而且还没查过详情（`detail_checked`）的卖出，每天最多 `pnl.detail_per_run` 张，按时间倒序补。查过一次就不再查（详情里没有到手价的单不会每天占着名额）；取自己悠悠 ID 失败只跳过这一步，快照照写。
3. **库存**：每页 1000，按 `totalCount` 翻页（平时 1 次，最多 10 页）；**租出**翻到 `hasNext = false`（最多 30 页）。翻到上限还没完就记 WARNING：少拿的会被算成去向不明。
4. 用 D 那天的 `price_daily` 计算（§4），写 D 的 `pnl_position`、`pnl_daily`（已有就覆盖：同一天重跑结果一样）。

- 出错：风控、限流、机房拦截按同步的规矩暂停账号通道，这一轮停在这里；已写进 `trade_order` 的保留，D 的快照这次不写，补跑时再来。登录失效：跳过这个账号。任何意外异常只记类型名，不影响监控。
- 启动补跑：和估值一样，D 的快照缺了、而且现在离 `run_at` 不到 12 小时，启动后补一次。
- 和监控轮次共用账号通道（同一个 `YoupinClient`）。夜里监控没停，只是每轮间隔加倍（夜间闸门），所以用 `rt.youpin_lock` 串行：监控整轮、心跳、看板「立即同步」、暂停单检查都持有它，盈亏任务只在发悠悠请求的那段持有（2026-11-24 写 plan 时改正；合并时改用暂停单检测加的这把锁，plan 偏离记录 1、11）。
- 请求量：平时每天 2 + 1 + 3 + 新卖出详情 ≈ 6～10 个（research §7）。

### 5.3 首次导入（CLI `pnl import`）

- 两个列表都翻到底（`max_pages` 放宽到 200），然后补全部卖出详情（作者账号 38 张，3 秒一张约 2 分钟）。打印每页条数、最早一笔的日期。
- 导入完立即跑一次 §5.2 的第 3、4 步，算出今天的快照。持仓模板第一次进 23:50 的快照之前没有 `price_daily`：导入时对这些模板现查一次 SteamDT 批量价（1 次/分钟，100 个一批），只用于这次快照，**不写 `price_daily`**（写了 23:50 那次会把它们当成「今天已有」跳过）。没配 SteamDT key 时退回库存 `marketPrice`（实现时加的：试导入时没现查，64 件没有市价、总盈亏差了一千多）。每批走共用时间槽 `wait_batch_slot`（和价格快照、选品、暂停单检查共用 1 次/分钟，跨进程）；暂停单检查或选品正在跑时干脆不补价，提示「今晚 23:50 的价格快照会补上」（2026-11-24：正式导入和暂停单检查同时跑，撞了 3 次 4005）。
- 上线时由 Claude 跑一次（会真的请求悠悠，约 20 页 + 38 个详情）。

## 6. 接口（只读库）

### 6.1 `GET /api/pnl?account=all|<id>`

```json
{"as_of": "2026-11-24", "computed_at": "…", "basis_default": "market",
 "accounts": [{"id": 1, "label": "账户 1"}],
 "realized": {"total": 322.77, "matched": 14, "unknown": 24, "unknown_net": 568.02},
 "holding": {"qty": 316, "cost": 10191.52, "value_mkt": 7133.76, "value_net": 6991.8,
             "unpriced_qty": 0, "flagged": 4},
 "where": {"inv": 222, "lease": 39, "unknown": 55, "unknown_cost": 3502.4},
 "youpin": {"pnl": -2063.27, "n": 201},
 "months": [["2025-05", 48.36], "…", ["2026-11", 40.58]],
 "categories": [{"key": "knife", "label": "刀", "qty": 4, "cost": 2559.0, "value_mkt": 1180.22, "value_net": 1156.7}],
 "notes": {"lease_qty": 54, "lease_rent_day": 1.04, "unbooked_inv_qty": 779, "unbooked_inv_value": 291.19}}
```

- `account=all` 把各账号相加，**每个号用它自己最新的那天**：某个号今天的任务失败，就用它上一次的快照；比最新的早 7 天以上的号（停用了）不再相加。`as_of` 是其中最新的一天。只有一个账号时前端不显示账户切换。卖出、已实现都只算到 `as_of` 那天结束（和持仓同一个时点）。（评审 2026-11-24 改。）
- `months` 从第一笔配上的卖出那个月到本月，没有卖出的月份是 0（不是缺数据）。
- 品类用 `analysis.category.categorize(hash_name)`，和总览同一套。
- 还没跑过（没有快照）：`as_of = null`，其余为空，页面显示「还没有数据，跑一次 `pnl import`」。

### 6.2 `GET /api/pnl/items?account=&sort=worst|best&q=&offset=&limit=`

每行：`template_id`、`name`、`sub`（磨损或类别）、`category`、`qty`、`cost`、`value_mkt`、`value_net`（缺价为 null）、`where`（`{"inv":1,"lease":0,"unknown":0}`）、`price_flag`、`realized`（这个模板累计已实现）。`sort=worst` 按浮动（按 `basis` 参数，默认市价）升序，`best` 降序；`q` 按名字搜。默认 `limit=50`。

### 6.3 `GET /api/pnl/sells?account=&limit=`

最近卖出，按时间倒序。每行：`at`、`template_id`、`name`、`sub`、`qty`、`net`、`net_exact`、`cost`（成本未知为 null）、`pnl`、`lots`（`[{"bought_at":"…","unit":100.0,"qty":1}]`）。默认 `limit=12`，「全部」时不限。

## 9. 和多账号、BUFF 的接口

- 所有表都带 `account_id`、`platform`；配对、对账是**全局**的（§4.1、§4.3）。
- **每日任务（2026-11-25 起）**：先把每个悠悠号（`rt.accounts`，持 `rt.youpin_lock`）、每个 BUFF 号（`rt.buff_accounts`，持 `rt.buff_lock`；BUFF 一轮也持这把锁）的订单和库存都拉完，再一次算账、写**全部号**的快照。任何一个悠悠号没拉成（暂停、掉登录、出错），这一天谁的快照都不写，页面继续显示上一天的（账缺一块会算错）；BUFF 号失败不挡。
- BUFF：~~BUFF 买的只和 BUFF 卖的配对~~ → **跨平台配对**（[ADR-0025](../../decisions/0025-pnl-cross-platform-matching.md)，用户 2026-11-24）：卖出先配同号同平台的批次，不够再配别的号、别的平台在它之前买的同模板批次。起因：正式库「去向不明」的 57 件大多是在 BUFF 卖掉或出租了。BUFF 那边要出：卖出记录（成交价、到手价或手续费）、出租中的列表、库存；在 BUFF 出租的算持仓。BUFF 订单接口、币种、手续费 1.5% 由 BUFF 期接入时补进 §2、§4。
- 接入 BUFF 之前，「去向不明」照旧这么叫、照算持仓（用户 2026-11-24：BUFF 接好了再一次改对）。2026-11-25 接上后改叫「不在库存」（§4.3）。
- BUFF 的卖出（`/api/market/sell_order/history`）和库存（`/api/market/steam_inventory`，force=0）字段已实测，见 [BUFF research](../../research/2026-11-24-buff-readonly-api.md) §9。**出租只在 BUFF App 里**（用户 2026-11-24 确认），网页接口拿不到，要另找 App 的接口；没拿到之前，BUFF 出租出去的件仍算「去向不明」。
- **BUFF 那边给什么**：见 [BUFF spec](2026-11-24-buff.md) §9。每天的盈亏任务里对每个 BUFF 号（`rt.buff_accounts`，不在 `rt.accounts` 里）调 `sync_buff_trades`，把 BUFF 的买入（求购成交、直接购买）、卖出（SUCCESS，`net_amount` = 平台给的 `income`）写进 `trade_order`（`platform='BUFF'`、一条一件）；`fetch_buff_holdings` 给库存 `(market_hash_name, template_id, assetid)`。
- **盈亏这边接上时要改的**（2026-11-24 和 BUFF 会话对过）：
  - 跨平台配对按 `hash_name`（market_hash_name）认同一个饰品，不按 `template_id`：BUFF 对不上悠悠模板的写 `-goods_id`。
  - 配对改成全局（跨号、跨平台），持仓快照怎么按号拆另定。
  - 库存：BUFF 库存就是绑定的 Steam 号的库存，和悠悠号绑同一个 Steam 号时是同一批货，按 assetid 去重。
  - BUFF 的增量同步也用「整页都是已知单才停、首次导入翻到底」（已请 BUFF 那边照悠悠的改）。
- 2026-11-25 已全部接上（plan（未公开））：接口按英文名合并单品（BUFF 独有模板的 `template_id` 给 null，不链详情页），卖出和配到的批次带平台；页面「去向不明」改「不在库存」，卖出写「悠悠卖出 / BUFF 卖出」「2025-10-23 悠悠买入 ¥301」。

## 11. 风险

- **去向不明 55 件、成本约 ¥3,502**（11-24 试算）：作者账号的库存、租出、在售里都没有。可能转到了另一个账户、在 Steam 上卖了，或者别的原因。按 §4.3 照样算进持仓。如果它们其实已经卖掉了，浮动会被低估（亏得少算了真实亏损，或赚得多算了）。多账号接入后先看能对上多少。
- **买入列表里的交易撤回**：Steam 7 天保护期内卖家撤回，悠悠那边订单会变成什么状态没实测（research §8）。如果撤回后订单仍是 340，会多出一个不存在的批次，最后落进「去向不明」。上线后留意。
- **悠悠订单列表不按我们以为的排**：增量同步靠「按时间倒序」，实测成立（research §2）。如果哪天变了，翻到已知订单号就停会漏单；首次导入后每周日加一次「翻到 `max_pages`」的全量复核〔未实现，二期再定〕。
- **卖出详情接口要 `userId`**：用 `get_user_info()` 取，失败时用估算的到手价，不阻塞。
- **SteamDT 价和悠悠成交价有差**：市价按在售最低，真卖时可能要让价更多；这正是「按到手价」口径的用处。
