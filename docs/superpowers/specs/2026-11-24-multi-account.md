# 悠悠多账号（第一期）

- 日期：2026-11-24
- 来源：intent（未公开）（接受）、[ADR-0022](../../decisions/0022-multi-account-first-then-buff.md)
- 状态：定稿（用户 2026-11-24：「定稿，继续」；还没有第二个号时，验收先用演示数据和库副本）
- 视觉基准：claude.ai 画布「SkinPulse 多账号视觉稿」（2026-11-24）：总览全部（深色）、总览只看小号（浅色）、系统页账号卡片（浅色）、添加账号（深色）。实现和视觉稿有出入时以本 spec 为准，本 spec 没写到的以视觉稿为准。

## 0. 一句话

一个服务实例同时监控几个悠悠号的求购单：每个号自己登录、自己失效提醒；告警、成交、市价提醒照旧按单走，多号时推送和看板标出是哪个号。**只有一个号时，行为、文案、看板和现在一模一样。**

## 1. 范围

**做：**
- 数据库、钥匙串、运行时里的「账号」从单例变成多行（§2～§4）。数据模型按 ADR-0022 给 BUFF 留好 `platform`，但本期只有 `youpin`。
- 每轮监控按号依次同步；只有同步成功的号参与这一轮的名次、告警（§5）。
- 推送多号时加简称；登录失效按号各推（§6）。
- 看板：顶栏账号切换、总览账号列、「前面是我自己的号」、系统页每号一张卡片、添加和停用账号（§7、§8）。
- CLI `set-token --account`、演示数据两个号（§9）。

**不做：**
- BUFF（第二期，ADR-0022）。
- 删除账号（只能停用；数据留着）。
- 跨账号的盈亏配对（盈亏统计那边定，本期只保证每张单、每个事件能查到账号，见 §12）。
- 简报页、选品页按账号切换：简报是已经发出去的消息的存档，选品的「已挂单」是按模板的。两页照旧显示全部，简报行里带简称（§6）。这一条比 intent 写的「跟着切换走」收窄了，理由如上。

## 2. 数据（迁移 0014）

| 表 | 改动 | 老数据 |
|---|---|---|
| `account` | 加 `platform`（String(16)，默认 `youpin`）、`label`（String(16)，可空）、`enabled`（Boolean，默认 true）、`device_id`（String(64)，可空）、`created_at` | 唯一那行：`platform=youpin`、`enabled=true`、`label` 空 |
| `my_buy_order` | 加 `account_id`（Integer，非空，默认 1，建索引） | 全填 1 |
| `order_event` | 加 `account_id`（同上） | 全填 1 |
| `system_status` | 账号通道的行改名：`youpin_account` → `youpin_account:1` | 迁移里改主键值 |

- **显示名**：`label` 或者悠悠昵称或者 `账号 <id>`，按这个顺序取第一个非空的。`label` 最长 8 个字（推送里放得下）。
- `purchase_no` 仍是主键：悠悠单号全站唯一，多个悠悠号不会撞（BUFF 加前缀是第二期的事）。
- 同一个悠悠号不能加两次：添加时校验出来的 `user_id` 和已有启用或停用的号相同就拒绝（「这个号已经在了」）。
- `account.id` 自增，停用不复用。

## 3. 凭据与设备身份

- 钥匙串：账号 1 沿用 `youpin_token`、`youpin_phone`（不搬，老用户零操作）；账号 N（N ≥ 2）用 `youpin_token:N`。`secrets.py` 加 `youpin_token_key(account_id)`，所有读写都走它。
- `device_id`：现在每次启动随机生成。改成按号持久化——第一次用到时生成并写进 `account.device_id`，之后一直用它。账号 1 也这样（第一次启动新代码时生成一次）。
- 匿名通道（公开队列、在售价）走**第一个启用的号**的 client：单号时和现在完全一样，同一个设备身份。

## 4. 运行时

```python
@dataclass
class AccountRuntime:
    id: int
    label: str           # 显示名，§2
    client: YoupinClient # 自己的 token、device_id、uk
    login_notice: LoginLostNotice

rt.accounts: dict[int, AccountRuntime]   # 只含 enabled 的，按 id 排
rt.client                                # 保留：= 第一个启用的号的 client（匿名通道、老代码路径）
```

- `build_runtime` 从库里读启用的号，逐个从钥匙串取 token。库里一个号都没有（新装）时，照现在一样建 `Account(id=1)`。
- 看板添加、停用、换 token 时就地改 `rt.accounts`，不用重启（和 PushPlus 的 `attach_channel` 一个思路）。
- `services/account.py` 的模块级 `_login_notice` 改成每个 `AccountRuntime` 一份。

## 5. 每轮监控

`Monitor.run_round` 的骨架：

1. 夜间闸门、`monitor_round` 打点：不变。
2. **按号依次同步**：对每个启用、未暂停的号调 `sync_my_orders(session, acc_rt)`，号与号之间等 `polling.account_gap_s`（新设置，默认 10 秒）。每个号的错误只影响它自己（见下表）。
3. **pass A 只处理这一轮同步成功的号的单**。同步失败的号，它的单这一轮不写快照、不走告警（不然会拿上一轮的名次再判一次），看板上显示的是它最后一次成功同步时的数据。
4. 实时核对、别处买盘、pass B、在售价、市价提醒、成交推送：对全部参与这一轮的单一起做，和现在一样。

**`sync_my_orders` 的改动**：
- 签名改成 `sync_my_orders(session, acc_rt)`；写的是 `account.id == acc_rt.id` 那一行。
- **「消失」只在自己号的单里判**：现在是「库里所有 active 的单，这次没看到就判消失」，多号后必须加 `MyBuyOrder.account_id == acc_rt.id`，否则同步主号会把小号的单全判成消失。这是本期最容易出错的一处，测试单独守（§11）。
- 新单写 `account_id`；`OrderEvent` 也写 `account_id`。
- 一张单出现在另一个号的列表里（理论上不会，单号全站唯一）：记一条 warning，改写成新号，不报错。

**错误怎么分号处理**：

| 异常 | 现在 | 多号后 |
|---|---|---|
| `LoginRequired`（84101） | 标失效、推登录失效、整轮结束 | 只标这个号失效、推这个号的提醒；**别的号照常** |
| `RateLimited` | 暂停账号通道 | 只暂停这个号（`youpin_account:N`） |
| `RiskControl`、`MachineRoomBlocked` | 暂停账号通道 | **暂停所有号**：这两类多半是按 IP / 设备来的，一个号撞上，别的号接着请求只会更糟。匿名通道不另外暂停：所有号都停了，这一轮本来就不会再发匿名请求 |
| `UkExpired` | 清 uk，本轮结束 | 清这个号的 uk，跳过这个号 |
| 其它 | 本轮结束 | 跳过这个号，记 exception |

所有号都失败时，这一轮和现在一样什么都不做。

**匿名请求按模板去重**：启用的号 ≥ 2 时，一轮之内同一个模板的公开队列只取一次（`dict[template_id, rows]`，只活一轮），几个号挂同一个模板时，实时核对、pass B 共用这一份。一个号时照旧每次现取：单号的请求行为一个都不变（实现时为了「单号零变化」收窄的）。

**深取**（匿名 20 行装不下时带 token 取全队列）：用这张单**所属号**的 client；`compute_rank` 的 `uid` 也是所属号的 `user_id`。

**成交去向**（`resolve_gone`）：按号分组，用各自的 client 翻「已完成」「暂停中」。翻页上限、退避沿用现在的设置，按号各算。

**心跳**：`job_heartbeat` 对每个启用的号各做一次，号之间隔 `account_gap_s`。

**一轮跑不完的提示**：一轮里同步所有号花的时间（含号间间隔）超过 `round_interval_min` 的一半时，日志记一条 warning，`/api/meta` 的 `service.issues` 加 `sync_slow`，系统页显示「账号或求购单过多，单轮接近超时」。用户 2026-11-24 确认最多 4 个号，正常到不了，这是保险。

## 6. 推送

- **多号 = 启用的号 ≥ 2**。只有这时才加简称；一个号时文案一个字不改（测试守住，§11）。
- 每张单的块：名字那一行前加 `[小号] `；单张的标题也加：`求购第1名：[小号] AK-47 | 红线`。
- 适用于：升到第 1 名、交易中、求购成交、市价提醒、简报的表格行。
- 登录失效：多号时标题 `悠悠登录已失效：小号`，正文不变；各号各自 24 小时重复。一个号时标题仍是 `悠悠登录已失效`。
- PushPlus 每小时 10 条所有号共用；同一轮几个号的同类推送照旧合成一条（现在就是按轮合并）。

## 7. 看板接口

**`/api/meta`**：
- 新增 `accounts: [{id, label, nickname, enabled, token: {valid, expires_at, days_left}, last_sync_at, paused_until}]`，启用的在前。
- 老的 `token` 字段保留，取**启用的号里最先到期的那个**（顶栏「token 快到期」的提醒抓最紧的）。
- `service.issues` 里的 `token_invalid`：任何一个启用的号失效就有；`not_logged_in`：一个登录过的号都没有。
- `setup.youpin`：有任何一个号登录过；`setup.first_round`：有任何一个号同步过。

**`/api/overview`**、详情页：
- 每张单加 `account_id`；响应加 `accounts: {id: label}`（只含有单的号）。
- 新字段 `own_ahead`：同一个 `queue_key` 上，**另一个号**有一张 active 的单排在我前面（价更高；同价按 `createTime` 早）时，`{label, price}`；否则 `null`。只查库，不发请求。

**账号管理**（都是同源 JSON 写接口，demo 下拒绝，限流同现在的换 token）：

| 接口 | 做什么 |
|---|---|
| `POST /api/youpin/token` | body 加可选 `account_id`（默认 1），其余不变 |
| `POST /api/accounts` | 添加：`{token, label?}` → 用新的设备身份校验 → 重号拒绝（409）→ 建行、存钥匙串、加进 `rt.accounts`、马上开一轮 |
| `PATCH /api/accounts/{id}` | 改 `label`、`enabled` |
| `POST /api/youpin/sync` | body 加可选 `account_id`；不给就按号依次同步全部 |

**停用一个号**：从 `rt.accounts` 拿掉；它的 active 单改成 `active=False`、告警状态回 NORMAL，**不记 `gone` 事件**（不是消失，不查去向、不推送）。钥匙串里的 token 留着。再启用时，下一轮它的单重新出现，按「新单」记，名次、告警从头算。不能停用最后一个启用的号。停用期间这个号的单如果成交了，**查不到**（它们已经不算活跃，不会再判消失），使用手册里写明。停用和正在跑的同步撞上时，同步结束前重读一次这个号，已停用就整次作废（评审 2026-11-24）。

## 8. 前端

三处改动，都只在**启用的号 ≥ 2** 时出现；一个号时页面和现在完全一样。

用户 2026-11-24 确认最多 4 个号，所以顶栏一直用分段控件，不做超过 4 个时的下拉框。

1. **顶栏「账号」切换**（`AppShell`）：分段控件「全部 / 主号 / 小号 …」，每个后面带单数，默认「全部」，选择记在 localStorage（读写包 try/catch）。只影响总览（标题行的计数、焦点卡片、表格、「最近成交」），所以**只在总览页显示**。顶栏的状态胶囊在某个号登录失效时显示「小号登录已失效」。
   - **2026-11-25 改**：切换从顶栏挪到**内容区右上角**（`AppShell` 里顶栏下面的 `.scope`，只在总览、盈亏出现）。放在顶栏时，这两页第一行放不下，导航被挤到第二行，换页时导航上下跳；现在每一页的顶栏都一样。
   - **2026-11-25 加**：`[dashboard] platform_names`（系统页「参数设置 › 看板显示 › 账号写成平台名」，默认关）。打开后切换和表格标签写「悠悠」「BUFF」；同一平台有几个号时写「悠悠 · 简称」（没改过简称用昵称）。后端算好放在 meta `accounts[].tag`、总览 `accounts` 和暂停单卡片的标签里；系统页卡片、推送、简报和「前面是我的小号」照旧写简称或昵称（同一平台里比，写平台名没有意义）。只有一个启用的号时，「看板显示」这一组不出现。
2. **总览表格**：「全部」时商品名后面一个小标签显示简称，**第一个号不带标签**（大多数单是它的，全带上太吵）；选了某个号时都不显示。`own_ahead` 有值时，「离第 1」那一格旁边一个提示：`前面是我的小号（¥351）`。筛选、排序逻辑放在 `overview/logic.ts`，带测试。
3. **系统页**：现在的账号卡片变成每号一张（简称、昵称、token 有效性和到期日、最近同步、「更新 token」「立即同步」「停用 / 启用」、改简称）；「添加账号」按钮在标题行右边，复用 `TokenDialog`，多一个简称输入框，并提示「用另一个浏览器或无痕窗口登录这个号」（同一个浏览器里切号会把原来的号退出）。失效的号卡片描边变成提醒色，主按钮是「更新 token」，并写明「这个号的单停在 HH:MM 的数据，不判名次、不推送」。一个号时只多一个「添加账号」按钮。
   - **2026-11-25 改（按平台分组）**：号 ≥ 2 时，系统页最上面的四张通道卡片不再出现，改成「平台和账号」：每个平台一整行，左边是平台标识（悠悠青色「悠」、BUFF 蓝色「B」）、几个号几张单和这个平台的通道状态（悠悠：匿名通道、账号通道；BUFF：最近一轮或「访问受限，暂停到」），右边是这个平台的账号卡片和「添加某某账号」（打开对话框时直接选好平台）。PushPlus、ntfy 合成一张「推送」卡片，和「排名核对」「每日简报」三张并排；「运行环境」改成整行横条，「最近推送」照旧整行。纯逻辑 `system/logic.ts::platformGroups`，带测试。一个号时页面不变。

## 9. CLI 和演示数据

- `set-token --account N`（默认 1）：N 不存在就在校验通过后新建。`probe-token` 不加：它只做诊断、不存东西，用哪个号的 token 都一样探测。
- `sync`、`round`：同步全部启用的号。
- `demo`：种两个号（「主号」「小号」），其中有一对单在同一个子队列，演示 `own_ahead`。

## 10. 设置

- 新增 `polling.account_gap_s`（默认 10，≥ 0）：一轮里号与号之间、心跳号与号之间的间隔。看板参数页可改。
- 其它设置都是全局的，不按号分。

## 11. 测试

- **单号零变化**：现有全部测试不改断言照样过；另加一组「一个号」的推送文案、`/api/meta`、`/api/overview` 快照，和改动前逐字一致。
- **消失只在本号判**：两个号，同步号 1 时号 2 的单一张都不能变成 `active=False`、不能有 `gone` 事件。
- 一个号 84101，另一个号照常同步、告警照常推；登录失效只推失效那个号。
- `RiskControl` 暂停所有号；`RateLimited` 只暂停一个。
- 同步失败的号，这一轮不写快照、不走告警。
- 匿名队列一轮内按模板只取一次。
- 深取用所属号的 client 和 `user_id`。
- `own_ahead`：价高、同价早、同价晚、不同 `queue_key`、同一个号的另一张单（不算）。
- 加号重号 409；停用不记 `gone`；不能停用最后一个。
- 迁移：老库升级后 `account_id` 全是 1、`system_status` 改名、`label` 空。
- 前端：`logic.ts` 的切换过滤、简称标签显示条件、`own_ahead` 文案。

## 12. 和并行的两件事

- **盈亏统计**（intent（未公开））：它的批次账每行带 `account_id`、`platform`，按「同账号、同平台、同模板」配对。本期的说法：**不跨账号配对，各号各算**；`my_buy_order`、`order_event` 的 `account_id` 就是它要的来源。两边都要加迁移，后合并的那个改编号。
- **暂停求购单检测**：「暂停中」按号查，用各自的 client；如果它先合并，本期把它的查询放进 §5 的按号循环里。

## 13. 验收

1. 测试实例（skill verify-dashboard，库副本 + 8799）：老库升级后看板和现在一样；demo 两个号时三处改动和视觉稿一致，浅色、深色各看一遍。
2. 正式环境：合并、重启后单号运行 24 小时，日志里每轮 `round:` 一行、`checked` 和合并前同量级，没有新的 warning。
3. 加第二个号（用户操作）：看板「添加账号」粘 token。跑一周，看日志里有没有 84101 以外的异常码、两个号的单有没有互相判消失；推送里带简称。
