## 1. 现状（11-24 用空库实测）

新装好、什么都没录的时候：

- 顶栏状态写「token 已失效」：其实是**从来没登录过**，「失效」会让人以为自己做错了什么。
- 总览标题「暂无求购进入前 2 / 还没有排名数据」，三张洞察卡全是 0，表格是空的。没有一句话告诉人下一步干什么。
- 系统页标题也是「token 已失效 / 还没有跑过一轮」；四个通道卡写着「未配置」，但没说怎么配置。PushPlus 只能在命令行里录。

## 2. 看板：「开始使用」卡片

### 2.1 什么时候出现

后端判断四步的状态，放进 `/api/meta` 的新字段 `setup`：

| 步骤 | 完成的条件 | 必需 |
|---|---|---|
| 登录悠悠 | 至少验证通过过一次（`Account.user_id` 不为空；没 token 时第一轮也会建一行 `Account`，所以不能只看有没有这一行） | 是 |
| 微信推送 | 配置了 PushPlus（或 ntfy） | 是 |
| 第一轮监控 | 同步成功过一次（`Account.last_sync_at` 不为空；`monitor_round.last_ok_at` 每轮开头就打，没登录也有，不能用） | 是 |
| 行情数据 | 配置了 SteamDT key | 否 |

卡片里按这个顺序排，顺序固定：完成的那一步原地变成一行打勾的灰字（「已登录 · token 还有 6 天到期」「已完成 · 同步了 12 张求购单」），当前要做的那一步按钮是主色，标题旁写「还差 N 步」（只数必需的）。

- **三个必需步骤都完成**之前，总览页最上面显示「开始使用」卡片，下面的洞察卡和表格照常显示（都是空的，不藏起来）。原来的大标题在第一轮跑完之前不显示（没有排名数据，「暂无求购进入前 2」没意义）。
- 全部完成后卡片消失，不留痕迹，不需要「关闭」按钮。老用户（已经全配好的）完全看不到它。
- 行情数据是可选的：没配置不挡住卡片消失。缺了它，大盘页和价位视图本来就有各自的「未配置」提示。
- demo 模式下 `setup` 视为全部完成。

### 2.2 每一步怎么完成

- **登录悠悠**：按钮「录入 token」，打开系统页现有的「更新 token」对话框（同一个组件），附一句怎么在浏览器里复制 token，链到使用手册。
- **微信推送**：按钮「录入 PushPlus token」，打开新对话框，写操作走新接口 `POST /api/pushplus/token`（见 §2.4）。另附一句「没有账号？去 pushplus.plus 用微信扫码登录，复制 token」。
- **行情数据**：只给命令 `uv run python -m skinpulse steamdt-key`（可复制），说明「可选：大盘、价位、选品要用」。不在看板里录：SteamDT key 录完还要跑一次 `steamdt-items`，一天只能一次，放在命令行里更不容易出错。
- **第一轮监控**：登录悠悠后就自动开始（监控不依赖推送：没配推送时告警只写日志），没登录时写「等登录」。跑完后如果你在悠悠上还没有求购单，卡片换成一句「监控在跑了，但你在悠悠上还没有求购单」，然后消失。

### 2.3 顶栏和系统页的说法

- `/api/meta` 的 `service.issues` 新增 `not_logged_in`（从来没有有效 token），排在 `token_invalid` 前面，两者互斥。顶栏显示灰点加「未登录」（不是警告色：没做完不等于出错），系统页标题「未登录悠悠」，副标题「录入 token 后开始监控」。
- 「token 已失效」只在**以前有效过**的情况下出现（现有行为）。
- 系统页 PushPlus 通道卡在「未配置」时加一个「录入 PushPlus token」按钮，和总览卡片里那个是同一个对话框（demo 下不显示）。

### 2.4 新接口 `POST /api/pushplus/token`

- 只收同源 JSON `{"token": "..."}`（和 `/api/youpin/token` 同一套检查）。demo 模式下 403。
- 校验和 CLI `pushplus-token` 完全一样：去掉首尾空白；中间有空白或不可打印字符直接 400。
- 发一条测试消息（复用 CLI 的那段文案）：
  - 成功：存钥匙串，并把 PushPlus 通道**原地加进**正在运行的推送器（不用重启），返回 `{"sent": true}`。
  - 失败：按业务码分开说「token 不对 / 要先实名 / 被限流」，**不保存**，原来的 token 不受影响。
- 限流：和换悠悠 token 一样，失败几次后要等一会儿。
- token 不进日志、不进响应、不进异常消息。
- 原地加通道：`FanoutNotifier.set_channel(name, client)`（新建 list 再赋值）；原来一个通道都没有（`rt.ntfy is None`）时新建一个，同时赋给 `rt.ntfy` 和 `rt.monitor.ntfy`（Monitor 启动时存了引用）。不改成「永远有一个空推送器」：好几处靠 `is None` 判断「没配通道 → 不推」。
- 页面上提示「已发一条测试消息到你的微信，看到了才算通了」（坑 1：「sent」≠ 送到了）。
