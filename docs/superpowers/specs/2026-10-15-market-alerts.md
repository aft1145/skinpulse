# 市价提醒设计规格（Market Price Alerts Spec）

- 起草：2026-10-15；2026-10-15 实现（plan（未公开））。来源：intent（未公开）
- 标记约定同主 spec：〔未实现〕表示还只是计划。

## 1. 两种情况

都只看「不限条件」、不在交易中、有在售价（`sell_depth > 0`）的单。

| 名字 | 条件 | 推送里怎么说 |
|---|---|---|
| `inverted`「榜首高于在售」 | 榜首价 ≥ 悠悠在售最低，且我排第 2～`rank_always`（默认 3）；或排第 `rank_always`+1～`rank_max`（默认 4～10）且我的价 ≥ 在售最低 × `inverted_ratio`（默认 0.85）。2026-10-15 用户要求「改成前三名或者达到一个比例才提醒」 | 前面的单可能很快被卖家吃掉，可能很快轮到我 |
| `near`「贴近市价」 | 我的价 ≥ 在售最低 × `near_ratio`（默认 0.9） | 一成交差价就很薄 |

两个都成立时一条里一起说。榜首价、名次用这一轮写进快照的值（经过实时核对的就用核对后的）。

## 2. 什么时候推

- 每轮在「升到第 1 名」之后、成交推送之前做。
- **候选**：用库里已知的在售价（可能是旧的）按 §1 判断成立的单。
- **探一下**（2026-10-15 评审后加）：第 2～`rank_max` 名、在售价超过 30 分钟没查过的单，即使按旧值不成立，也在核对名额里排在候选之后实时查一次——在售价跌到榜首之下这件事，旧值看不出来。
- **核对**：推送前给每张候选单用公开接口查一次实时在售最低（`get_on_sale`，和市场价刷新同一个方法、同一个令牌桶），写回 `sell_min / sell_depth / sell_checked_at`，再按实时值重判。每轮最多核对 `verify_max`（默认 5）张：先核对名次靠前的，没核到的下一轮再核。
- **一段只推一次**：每张单记 `market_flag`（现在成立的情况，NULL = 都不成立）和 `market_notice`（这一段的推送状态：sent / failed / suppressed）。
  - 情况从「都不成立」变成成立 → 新的一段，待推；
  - 推送成功 → sent，这一段不再推；
  - failed、suppressed（撞上每小时上限）→ 下一轮重试；
  - 重新判断都不成立（用实时值，或者名次 / 我的价变了）→ 清空两列，下次成立是新的一段。
  - 只多了一种情况（比如原来只有 `near`，现在又 `inverted`）不算新的一段。
- 同一轮的多张单合成一条消息；占用 `alerts.hourly_cap` 的一个名额，和其它推送一样。
- 改价后按新价重判：用户把价改低了，`near` 自然就清掉；只要还有一种情况成立，就是同一段、不重推（2026-10-15 实现时定，见 plan 偏离 1）。单子消失时清空。

## 3. 消息

- 标题：一张时「榜首高于在售 · 名称」或「贴近市价 · 名称」（两种都有时写「榜首高于在售」）；多张时「N 张求购接近成交价」。
- 每张：名称（简称）；`我的价 1.10 · 第 4 名`；`榜首 1.30 · 悠悠在售最低 1.17（10 件）`；一句说明：
  - `inverted`：「榜首比在售还高，前面的单可能很快被卖掉，轮到你」；
  - `near`：「我的价是在售的 94%，成交后扣费差价约 +X%」（扣费口径同价位 spec §4.3 的到手价，只按悠悠：在售最低 × (1 − 让价) × (1 − 1%) × (1 − 提现 1%)）。
- 末行「核对于 HH:mm」。

## 4. 看板

- 总览排名视图的「离第 1」列下面加一个标签：「榜首高于在售」（warn）/「贴近市价」（amber），两种都有时都显示。
- 来自行里新字段 `market_flag`（`inverted` / `near` / `both` / null）。看板只读库，不请求悠悠。
- 系统页「最近推送」认识新事件 `MARKET`。

## 5. 配置 `[market_alerts]`

```toml
[market_alerts]
enabled = true
rank_always = 3     # inverted：第 2～3 名一律提醒
rank_max = 10       # 第 4～10 名要我的价 ≥ 在售最低 × inverted_ratio
inverted_ratio = 0.85
near_ratio = 0.9    # near：我的价 ≥ 在售最低 × near_ratio
verify_max = 5      # 每轮推送前最多实时核对几张
```

### 5.1 0.85 的来历（2026-10-15）

[价位回测报告](../../research/2026-10-09-valuation-backtest.md)的成交描述：16 笔确认成交的「求购价 ÷ 当天悠悠收盘」是 0.68、0.74、0.81、0.84、0.85、0.85、0.87、0.89、0.89、0.90、0.91、0.91、0.91、0.97、0.98、1.01，四分之三在 0.85 以上。名次靠后（第 4～10）的单，只有出价接近市价才可能在倒挂时轮到。成交到 50 条以上时重看这个数。

## 6. 测试

- 纯逻辑：两种条件的边界（正好等于、名次 1 / 2 / 5 / 6、条件单、交易中、无人在售、缺价）。
- Monitor：候选 → 核对（实时价让情况消失就不推）→ 推送 → 一段只推一次 → 情况消失后重新布防 → failed 重试 → 每轮核对上限。用假客户端。
- 消息：单张、多张、两种都有。
- 接口：`market_flag`；前端：标签文案。
