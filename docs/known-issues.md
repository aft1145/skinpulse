# 已知问题（还没排期）

从 STATUS 挪出来的（2026-11-20）：这些不影响「此刻」该做什么，按需再看。修掉一条就删一条；要排期的写成 intent。

1. 「悠悠登录已失效」推送不记 `notification_log`，看不出发没发出去（10-26 起改成失效时推一条、之后每 24 小时一条，见 `services/account.py` 的 `LoginLostNotice`）。
2. `hourly_request_cap` 只统计抽样核对、实时核对、市场价刷新、市价核对；同步、心跳、`deviceW2`、深取、SteamDT、成交去向查询都没计入。
3. PushPlus 真实送达没有自动核验；正文长度上限没实测（简报按 16000 字节截断）。
4. 夜间闸门放行时就记时间，随即撞上风控暂停的那一轮也算用掉了（有意为之）。
5. `uv run ruff check` 有约 281 条历史遗留提示；F/E9 为 0，由 hook 守住。
6. 简报推送成功后 `brief_log` 提交失败会丢记录，12 小时内启动补发可能重发；简报的串行锁只在进程内。
7. 调低 `enter_rank` 正赶上一轮时，可能有单留在 ALERTING 到重启；重启会重新布防，可能再推一次（有意：宁可重复，不能漏）。
8. 白天手动跑 `price-snapshot` 会冻结当天的在售列。
9. 09-24 之前 CSMONEY 等四个平台的全空行还在（约 1500 行），无害。
10. `/api/overview` 每轮后第一次约 0.4 秒（spec 定 300 ms，已记偏离）；`/api/analysis` 每天第一次约 0.76 秒。
11. CLI `login`（短信登录）走不通（`doLogin` 返回 `-4`）。
12. 「减少动态效果」没法在内置浏览器里模拟，只核对了代码。
13. 系统页标题说不出「PushPlus 连续失败 N 次」。
14. 09-30 的简报缺了，用户决定不补。
15. `CategoryPicker`、`GapPicker`、`RestartButton`、价位表头建议筛选、选品页没有组件测试，只测了纯逻辑和接口、手测过。
16. 回测的成交描述每条两次查询（N+1）。
17. 在正式库上再起一个 `run --web-only` 会把正在跑的选品标成中断（skill verify-dashboard 要求测试实例用库副本）。
18. 电击枪（Zeus x27，含 StatTrak™、纪念品共 64 个模板）在品类里归「其他」，选品、总览品类筛选都在「其他」下面（2026-11-23 发现）。
19. 推测成交（ADR-0018）可能误记：卖家发货前取消交易、紧接着用户自己撤单，也会被记成推测成交。还没出现过。
20. 系统页「重启服务」点了以后「服务回来就自动刷新页面」只看过代码：测试实例上服务确实退出了（退出码 143），但 preview 重启实例会重开标签页，没法模拟 LaunchAgent 拉起后的自动刷新。
21. 总览价位视图的「可以加价」建议没用 R3（刚从低点涨上来）；要用另写 intent（ADR-0019）。
22. 系统页「重启服务」平时只在「运行环境」卡片底部，第一屏看不到（只有「代码已更新」时才在标题旁边）。Windows 真机验收时用户第一眼没找到（2026-11-24）。
23. 从没录过悠悠 token 时，系统页标题写「还没登录悠悠」，「悠悠账号」卡片却写「token 已失效 / 读不到到期时间」，应该也写「还没登录」（2026-11-24 Windows 真机验收发现）。
24. Windows 上服务被强制结束时，`supervisor.log` 把退出码记成 `4294967295`（-1 的无符号写法），只是难看。
25. Windows `service install --settings 别的.toml`：Run 键的命令只带 `--root`，登录后拉起的服务用的是仓库里默认的 `settings.toml`；`status` / `stop` 却按 `--settings` 的 data 目录查 pid（旧版快捷方式也一样）。要用别的配置文件就别用 `service`（2026-11-24 评审发现）。
26. Windows `service status` 比较目录是按字面：通过 subst 盘符、目录链接或 8.3 短名进同一个仓库时，会误报「指向另一个目录」（重新 install 一次就对上了）。
27. BUFF（BUFF spec）：`session` 实际能用几天、「交易中」时订单的 `state` / `progress` 取值、一轮里成交超过 20 笔时配对漏看，都要等上线后看日志（`buff round:` 一行、`buff: order … in trade`）。BUFF 的买卖、库存 11-25 起已进盈亏配对和持仓（ADR-0025）；BUFF App 里的出租网页拿不到，那部分算「不在库存」。
28. BUFF 没轮到数名次的普通单，名次记「未知」、榜首记最高普通单价；单多到超过 `queue_per_round` 时，总览上这些行的名次会轮流出现、轮流变成「—」。
29. 加 BUFF 号时，如果那个号一张求购单都没有，`wait_supply` 里读不到用户号，查重就跳过了：同一个 BUFF 号能加两次（评审 2026-11-24）。加号前先挂一张单，或加完看系统页有没有两张 BUFF 卡片。
