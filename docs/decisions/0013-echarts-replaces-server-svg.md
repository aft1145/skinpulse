# 0013. 看板图表改用 ECharts，取代服务端生成的 SVG

- 日期：2026-09-27
- 状态：生效
- 拍板：用户
- 取代：[ADR-0004](0004-server-side-svg-charts.md)

## 背景

ADR-0004 选择在服务端生成静态 SVG，理由是「交互（缩放、悬停）目前用不上」，那时就说好了「以后需要交互式图表时再重新考虑」。现在看板改版（[ADR-0012](0012-dashboard-vue-spa.md)），用户要的正是这些交互：十字光标、悬停数值、拖动缩放、切换时间范围，还有图表入场动画。

## 决定

- 图表一律用 **ECharts**，按需引入：只打包用到的图表类型和组件。饰品 K 线、大盘走势、排名走势、排名分布、平台比价都用它画。
- 保留的规则：涨红跌绿；K 线纵轴按实体定范围，离谱的影线截断，并在图上注明截断了几根、极值是多少；我的求购价在 K 线图上画成一条虚线。
- 服务端的 `web/charts.py` 在三期删除（实际二期就删了：两个 Jinja 页面迁走后它就没人用了）。接口改为返回原始的 K 线数据（时间、开、收、高、低），均线由前端计算，或者由后端和信号一起返回。
- 补记（2026-09-27，二期）：详情页的「各平台比价」最后用 HTML/CSS 画，没用 ECharts。视觉稿是每行带精确数字的表，条形只是辅助；HTML 版读屏能按行读出来。其余图表照本 ADR 用 ECharts。

## 否决的方案

- **TradingView lightweight-charts**：体积小（约 45 KB），行情手感好，但只擅长画行情图，排名分布、比价这类图画不了。
- **继续用服务端 SVG，再加一段悬停脚本**：不用引入图表库，但要自己实现缩放和动画，做到一半就相当于重写了一个图表库。

## 影响

- ADR-0004 的状态改为「被 0013 取代」。
- 图表的正确性不再能用 Python 单元测试直接覆盖。改为：后端测试返回的原始数据（包括截断标记），前端用 vitest 测数据转换函数（均线、坐标轴范围、截断）。
- 首页不加载 ECharts：它按路由拆分打包，只在有图表的页面加载。
