# 0012. 看板改为 Vue 3 前后端分离，构建产物进仓库，由 FastAPI 同端口提供

- 日期：2026-09-27
- 状态：生效
- 拍板：用户

## 背景

看板原先是 Jinja 模板 + HTMX + 一个 11 行的 CSS（spec §9）。用户要求把它做得好看、易读、有交互和动效，还要能在 Mac 和 Windows 上都直接用（intent（未公开））。

## 决定

- 前端用 **Vue 3 + Vite + TypeScript + Naive UI**，源码放 `frontend/`，页面由前端路由负责；后端只提供 `/api/*` JSON。
- **构建产物提交进仓库**（`skinpulse/web/dist/`），由 FastAPI 在原来的 8766 端口提供静态文件和前端路由的兜底。服务仍是一个进程，launchd 和部署方式都不变。拉代码后不需要 Node；只有改前端的人要装 Node，开发脚本 Mac 和 Windows 都能跑。
- 分三期迁移，每期上线的页面替换对应的 Jinja 页面，三期做完删掉 Jinja 模板和 HTMX。

## 否决的方案

- **保持服务端渲染、手写 CSS**：不需要任何工具链，改动风险最小。但用户要的交互（虚拟滚动表格、可缩放图表、命令面板、成体系的动效）用组件库做起来成本低得多。
- **部署时在 Mac 上构建**：仓库更干净，但 Mac 和 Windows 都得装 Node，拉代码之后多一步，容易忘。
- **前端单独起一个服务**：要多管一个常驻进程和端口，对个人服务来说太重。
- **Element Plus**：国内资料最多，但视觉偏传统后台，暗色模式要额外配置。Naive UI 原生支持主题切换，数据表格也更强。
- **不用组件库、全部自己写**：外观完全可控，但表格、弹窗、提示这些都得自己造，工作量太大。

## 影响

- 仓库里多了一套前端工具链（`frontend/package.json`、`package-lock.json`）和一份构建产物。改了前端必须重新构建并提交产物，有测试检查产物和源码是否一致（见 spec）。
- `/api/*` 从「给模板顺便用的附属接口」变成看板唯一的数据来源，接口的形状要按新页面重新整理：返回原始数值和 UTC 时间，由前端负责格式化。
- 所有 POST 接口必须加上 Host / Origin 校验，并且只收 JSON，防止跨站请求（spec §6）。
- spec §14 的「M4 Vue 前端」由这次改版完成。
