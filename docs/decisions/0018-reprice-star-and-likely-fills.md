# 0018. 改价时的「*」靠 createTime 区分；交易中过又查不到去向的记「推测成交」

- 日期：2026-11-23
- 状态：生效
- 拍板：用户（在 A 事后更正 / B 晚一轮再推 / C 看 createTime 里选了 C，并加上推测成交）

## 背景

悠悠改价是撤单重挂，过渡的一小段时间里旧单的 `rank` 也是 `*`，11-23 玛珀丽一次改价被推成「交易中」。同一天一张纪念包真成交了，却不在「已完成」和其余所有 status 的列表里，被记成撤单。见 intent（未公开）、[live-api-findings §7](../research/2026-09-06-live-api-findings.md)。

## 决定

- 看到 `*` 时和上一次同步的 `createTime` 比：没变 = 改价过渡，不算交易中；变了（被卖的时刻）才算。第一次看到就是 `*` 的照旧算。
- 消失时还在交易中的 `gone` 事件记 `in_trade_at`；两个列表都翻完还没有的，记 `likely_done`（推测成交），时间取被卖的时刻，**不推送**，看板「最近成交」标「推测」。

## 否决的方案

- **A 事后更正**：照旧误推再补一条更正；而且「旧单消失 + 同一饰品冒出新单」在纪念包那里是「成交后另建新单」，会把真成交误判成改价。
- **B 连续两轮才推**：真成交从被卖到成交常常只有 3～5 分钟，交易中基本就不推了。

## 影响

- `services/account.py`（同步时判交易中）、`services/fills.py`（`likely_done`）、迁移 0012、[成交推送 spec §4](../superpowers/specs/2026-10-02-fill-alerts.md)。
- 推测成交可能误记：卖家发货前取消、紧接着用户自己撤单。出现了再看。
