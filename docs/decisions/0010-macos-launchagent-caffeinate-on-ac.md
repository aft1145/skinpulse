# 0010. macOS 自启用 LaunchAgent，接电源时用 caffeinate -s 防睡眠

- 日期：2026-09-24
- 状态：生效
- 拍板：用户认可 Claude 的建议

## 背景

服务已按 [ADR-0009](0009-run-service-on-macos.md) 迁到 Mac（2026-09-24 接手完成，手动在终端里跑）。这台机器是 **MacBook**，系统设置里接电源和用电池都是空闲 1 分钟就睡。Windows 上的自启没有失败重启（[ADR-0005](0005-windows-autostart-startup-folder.md)），监控停摆过好几次。选项见 intent（未公开）。

## 决定

- **自启**：用户级 LaunchAgent（`~/Library/LaunchAgents`，不需要管理员）。`RunAtLoad` 负责登录即起，`KeepAlive` 负责崩了自动拉起。
- **睡眠**：服务在跑、**且接着电源**时，用 `caffeinate -s` 阻止系统睡眠；屏幕照常熄灭。用电池时、合盖时照常睡。caffeinate 的生命周期绑在服务进程上：服务停了，防睡眠就跟着解除。
- 合盖或用电池睡着期间错过的监控不补。00:00 简报靠现有的启动补发（12 小时内）兜底，23:50 价格快照错过就没有了。

## 否决的方案

- **登录项 + 启动脚本**：会开一个终端窗口，而且崩溃后不会重启，等于把 Windows 上的老问题搬过来。
- **`caffeinate -i`（用电池时也不睡）**：监控更完整，但电池会被一直消耗。
- **什么都不做**：空闲 1 分钟就睡，不用电脑的时候基本等于没有监控。
- **`sudo pmset repeat wake` 每晚 23:48 唤醒**：要管理员权限，合盖时唤醒的时间很短、不可靠。以后如果 23:50 的快照缺得多，可以再叠加。

## 影响

- 接着电源时，这台 Mac 在服务运行期间不会自己睡着（屏幕照常熄灭）。想让它睡，要么合盖，要么停掉服务。
- 服务从 launchd 启动，不会读 `~/.zshrc`，环境变量和终端里不一样。这正是 [ADR-0011](0011-http-clients-ignore-env-proxy.md) 要统一的地方。
- 同一台机器上还是可能出现两个实例：launchd 拉起了一个，用户又在终端里手动跑了一个。所以要加单实例锁，见 spec §11。
- 2026-11-23 补：看板「系统」页可以一键重启（服务给自己发 SIGTERM，靠 KeepAlive 拉起），见 intent（未公开）。开机自启不做看板开关。
