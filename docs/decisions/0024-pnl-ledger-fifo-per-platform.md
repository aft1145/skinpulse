# 0024. 盈亏：自记批次账，同账号同平台同模板先进先出

- 日期：2026-11-24
- 状态：生效；「只在同平台配对」被 [ADR-0025](0025-pnl-cross-platform-matching.md) 取代（2026-11-24）
- 拍板：用户（接受 intent（未公开），逐条回答了开放问题）

## 背景

要统计盈亏。悠悠有只读接口能拿到买入、卖出（含扣完手续费的到手价）、库存（带悠悠记的买入价和市价）、租出中的饰品（[research](../research/2026-11-24-pnl-data-sources.md)）。作者账号买得多、卖得少，盈亏的大头在持有中的饰品，其中按价值将近一半租出去了，不在库存接口里。

## 决定

- **自己记批次账**：每一笔买入是一个批次，卖出按规则消掉批次，没消掉的就是持仓（不管在库存、租出还是在售）。悠悠库存接口算的浮动盈亏只做对照。
- **配对**：同账号、同平台、同模板，先进先出。哪里买就在哪里卖，悠悠买的不和 BUFF 卖的配对。配不上的卖出记「成本未知」，不算进盈亏，单独列出。
- **范围**：每个账户的全部买卖历史（悠悠能翻到多早就从多早开始），不只是 SkinPulse 监控过的求购。统计两个账户。
- **已实现** = 卖出到手价（悠悠订单详情的 `revenue.amount`，已扣卖出手续费）− 配到的成本。**提现费默认不扣**。
- **浮动**：按市价、按到手价两种都算，页面可切换，**默认按市价**。
- **租金不算**（拿不到到账历史）。
- 每一行都带 `account_id`、`platform`。

## 否决的方案

- **直接用悠悠库存接口的买入价和浮动盈亏**：租出去的饰品不在里面；买入价怎么来的不透明；BUFF、第二个账户接不进来。
- **按 assetid 逐件配对**：Steam 一交易就换 assetid，买入记录里的号在自己库存里对不上。
- **按同模板平均成本**：和先进先出比，差别只在同模板多件、买价相差大的少数情况；用户选了先进先出。

## 影响

- 已实现盈亏和价位 spec 的「到手价」口径不同：那边扣提现费（「卖了能拿走多少」），这边不扣（钱留在余额里接着挂求购）。
- 买入列表最早一笔之前买的、别处来的饰品没有成本，卖出时不算盈亏；库存里没有买入记录的饰品不进持仓，只在页面上一行带过。
- 盈亏不读 `order_event`，推测成交不影响盈亏。
