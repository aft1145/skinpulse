# 0020. 开源：私有仓库开发，过滤后导出到组织下的公开仓库

- 日期：2026-11-23
- 状态：生效
- 拍板：用户（选了「组织下新仓库」「MIT」「敏感代码保留加免责」「公开设计、私藏流水」「私有仓库开发、定期导出」）

## 背景

要开源，但私有仓库历史里有 QQ 邮箱，日常文档（STATUS、intent、plans）里有个人交易信息，工作流也依赖这些文档。见 intent（未公开）。

## 决定

- 开源仓库放在现账号新建的 GitHub 组织下，许可证用 MIT。
- 继续在私有仓库开发。`scripts/export_public.py` 把过滤后的快照写进公开仓库的本地 clone，由用户检查后提交、推送。所以公开仓库的历史是一段一段的版本提交。
- 公开仓库才有的文件放在 `public/`，导出时覆盖同路径的文件；不公开的路径写在 `.publicignore`。
- 导出前跑泄露检查，命中就失败退出。

## 否决的方案

- **把私有仓库直接改成公开**：历史里有 QQ 邮箱和已删文档的旧版本。
- **注册第二个 GitHub 个人账号**：违反 GitHub 条款（一人只能有一个免费个人账号），也藏不住身份。
- **改到公开仓库开发**：个人文档得挪到单独的仓库，工作流要改，而且以后每个提交都要提防带上个人信息。

## 影响

- 新增 `public/`、`.publicignore`、`scripts/export_public.py` 及其测试。
- 要公开的文档、fixture、测试改成脱敏版本。
- 以后新增的文档要想清楚公不公开；不公开的路径加进 `.publicignore`。
